可以试试

  1. 看两边的锁屏推送：左边凌晨 00:40 就开始响，一天响四十多次，两条告警一条都没响。
  2. 点「播放这一天」，或把时间拖到 07:59 再拖到 08:00：右边夜里攒下的动态在 08:00 合成一条送达，告警单独送。
  3. 在右边「新内容」分类查看各篇标题；点某个频道的推送开关，只改变 App Push。
  4. 切到通知设置：保留逐频道选择，将关注与点赞分级。关闭点赞推送后，站内消息仍在。
  5. 关掉「预设两次全部已读」，模拟一整天没有主动清除通知，对比两边角标。

示例用户创建了两个频道，也订阅了其他频道；新内容提醒统一按订阅者身份处理，不因频道由自己创建而单独成类。示例包含内容、互动、运行告警和账户积分告警。人物与标题均为虚构。右侧时间与频控数值是待评审参数，不代表已上线规则。

策略以方案文档为准

本 Artifact 演示四分类、内容标题、账户级告警、逐频道 Push 和点赞时间窗聚合。完整通知类型、触发条件、数量上限、跨端已读及异常场景，均在方案文档中逐项定义。

本公开页面仅展示 UI 原型，方案文档单独提供。

“点赞聚合示例”会开启赞类 Push 并定位到14:00，展示同一小时不同作品的赞合为一条推送。默认设置仍关闭赞类 Push。模拟中的数字仅用于对比，不是线上收益预测。

App 改造版与 Web 共用演示通知已读和内容已看状态，可在任一端清除通知或打开具体标题。通知设置中的 App Push 和邮件开关独立，逐频道设置只影响 App Push。本地演示不连接生产接口，不会发送真实通知；尚未覆盖真实跨设备网络同步、退款撤销和全部子类频控。

调整设置会按当前规则重新演算示例当天的推送，方便比较策略，不代表真实已发记录可被撤回。生产中的偏好变更仅影响待发通知，不重置已发记录与预算。
